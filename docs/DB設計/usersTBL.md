# DB設計

## テーブル名：users

### 概要
ユーザー情報を管理するテーブル。

### カラム定義

| No. | 論理名 | 物理名 | データ型 | 桁数(最大) | NULL | PK | FK | UNIQUE | DEFAULT | 制約・チェック | 備考 |
|---:|---|---|---|---:|---|---|---|---|---|---|---|
| 1 | ユーザID | user_id | UUID | - | × | ○ | - | - | - | - | 本テーブルの主キー。 |
| 2 | ユーザネーム | username | TEXT | 15 | × | - | - | ○ | - | - | 同一usernameを持つ複数ユーザの登録を防ぐため |
| 3 | パスワードハッシュ | password_hash | TEXT | - | × | - | - | - | - | - | ユーザが登録したパスワードをハッシュ化して保持する |
| 4 | 作成日時 | created_at | TIMESTAMP | - | × | - | - | - | NOW() | - | - |
| 5 | 更新日時 | updated_at | TIMESTAMP | - | × | - | - | - | NOW() | - | 現状は使用用途なし。将来的なユーザネーム変更等機能追加あれば使用する |

### テーブル間の関係
usersテーブルに対してurlsテーブルは、1対多の関係（1ユーザは複数urlを登録しうる）
usersテーブルに対してsessionsテーブルは1対多の関係（セッションが積み重なることがありうる）
