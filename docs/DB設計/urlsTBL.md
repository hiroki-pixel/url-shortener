# DB設計

## テーブル名：urls

### 概要
ユーザーが登録したURL情報を管理するテーブル。

### カラム定義

| No. | 論理名 | 物理名 | データ型 | 桁数 | NULL | PK | FK | UNIQUE | DEFAULT | 制約・チェック | 備考 |
|---:|---|---|---|---:|---|---|---|---|---|---|---|
| 1 | urlID | url_id | UUID | - | × | ○ | - | - | - |  |  |
| 2 | ユーザID | user_id | UUID | - | × | - | ○ | △1 | - | - | usersテーブルにデータがない場合、本テーブルにも格納しない。original_urlとの組み合わせで一意にする。 |
| 3 | オリジナルURL | original_url | text | 2048 | × | - | - | △1 |  | URLの形式となっているかのチェック(AP側で実施) | ユーザからの入力情報。user_idとの組み合わせで一意にする。 |
| 4 | メモ | memo | text | 256 | ○ | - | - | - | - | - |  |
| 5 | ショートコード | short_code | text | 6固定 | × | - | - | ○ | - |  |  |
| 6 | 作成日時 | created_at | TIMESTAMP | - | × | - | - | - | NOW() | - | - |
| 7 | 更新日時 | updated_at | TIMESTAMP | - | × | - | - | - | NOW() | - | 現状は使用用途なし。オリジナルと短縮版の対応変更等の機能追加あれば使用する |

#### 補足
△n：複合UNIQUE制約の構成カラム(同じn同士で複合の組み合わせを意味する)

### 外部キー

| 外部キーカラム | 参照先テーブル | 参照先カラム | 備考 |
|---|---|---|---|
| user_id | users | user_id | usersテーブルに存在するユーザのみ登録可能とする。URL情報がどのユーザに紐づくか管理する |

### UNIQUE制約

| 対象カラム | 備考 |
|---|---|
| short_code | 生成されるコードは一意である必要があるため |
| user_id, original_url | 同一ユーザによる、重複URL登録を禁止するため |

### INDEX

| INDEX名 | 対象カラム | UNIQUE | 用途・理由 |
|---|---|---|---|
なし
リダイレクト機能で検索キーとなるshort_codeはUNIQUEのためインデックスが作成される
user_idについても、user_idとoriginal_urlの複合UNIQUE制約によりインデックスが作成される

### テーブル間の関係
usersテーブルに対してurlsテーブルは、1対多の関係（1ユーザは複数urlを登録しうる）
